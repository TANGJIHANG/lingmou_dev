# D0–D7 竖线打通计划

## 目标

**先打通一条最窄的竖线**，而不是七块积木同时抓：

> 一张图 → 模型出框 → 导出 ONNX → 用 ONNX Runtime 推理 → **框与 PyTorch 结果一致**

这条线打通，就理解了后续 80% 的工程卡点（尤其 D6 的精度对齐，是上板后最容易出问题的环节）。
之后再横向补宽度。

## 硬约束

1. **D2 数据集：不碰 DOTA 全量**（数十 GB + 格式转换，可吃掉三天）。
2. **第一版类别数 ≤3 类**。类别多寡不影响链路是否通，只影响你几天能跑通。
3. **D5–D6 在 WSL2 / Linux 上做**（理由见 `docs/decisions.md`；环境已就绪，见 `docs/env.md` 第 5 节）。
4. **不引入 Ultralytics**（AGPL-3.0，交付许可风险）。
5. **每个阶段都留证据物**：截图、日志、录屏、数据表，注明来源与日期。
6. **产出的 ONNX 必须显式设置 `ir_version`**，并通过 `tools/backend_smoke.py` 验证可加载。
7. **任何消融实验前，必须先让训练可复现（固定随机种子 + `cudnn.deterministic`）。**
   D8+ 计划里有结构化剪枝、INT8 量化、蒸馏、结构重构——**每一项都需要消融记录**。
   而不固定种子的单次配对实验，其差异**无法与 run-to-run 方差区分**：
   本项目已实测过一次（`drop_emptied` 消融，见 `docs/decisions.md`）——
   A 与 A2（同数据、仅换种子）之间召回差 2 个框，与 A 与 B（换数据集）的 3 个框**同量级**，
   即那次观测到的"召回差异"全部是噪声。
   **在可复现性做掉之前，消融记录会生成一批不可解读的数字，反而是负资产。**

### 可复现性（硬约束 7 的落地）

`scripts/train.py` 目前**没有固定种子**，这是已知缺口。补齐时应：
- `random` / `numpy` / `torch` / `torch.cuda` 全部播种，并写入配置与权重；
- 打开 `torch.backends.cudnn.deterministic = True`、关掉 `benchmark`；
- **记录代价**：deterministic 会变慢——这属"可复现 vs 跑得快"的取舍，
  必须实测两个模式的耗时差并记进 `docs/decisions.md`，不能悄悄打开；
- 完成后**验证**：连跑两次同配置，`best.pth` 的 SHA256 应当一致
  （注意：还需确认 cuDNN 是否真的给出逐位一致的结果，**这一点必须实测，不能假定**）。
