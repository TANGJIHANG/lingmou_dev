## 2026-09-23 · 首期检测框架暂不定为 MMDetection

- **决定**：第一周竖线（D1–D7）用 torchvision 自带检测模型或 RT-DETR 打通；
  MMDetection / MMRotate **暂缓**，D2–D3 拿到真实数据后重新评估。
- **理由**：
  1. 实测 OpenMMLab 预编译轮子索引：`cu124` / `cu126` / `cu128` 路径**全部 404**，
     可用组合最高只到 **cu121 / torch2.2**（`cu118/torch2.0`、`cu121/torch2.1` 等）。
  2. 本机 RTX 5060 需 **cu128+**（CUDA 12.8 才含 sm_120），已装 torch 2.14.0+cu130，
     与 mmcv 轮子上限差距进一步拉大。
  3. 该索引中 Windows 轮子（`win_amd64`）仅存在于远古版本 `1.1.5/torch1.6`。
     → 在 Windows 上用 MMDetection ≈ **用 MSVC 源码编译 mmcv**，纯消耗且产出仍指向 cu121。
  4. 第一周竖线的价值在**打通链路**（图 → 检测 → ONNX → ORT），不在框架选型。
- **备选与放弃原因**：
  - **MMDetection / MMRotate**（方案原定）：保留为候选，等确定用 Linux/aarch64 环境或
    确认可编译后再启用；旋转框（DOTA/OBB）最终大概率仍需它或等价能力。
  - **PaddleDetection**（Apache-2.0）：无需 mmcv、含旋转框、有 Paddle2ONNX，值得在 D2–D3 一并评估。
  - **Ultralytics YOLO**：**明确排除**。全系 AGPL-3.0 强传染许可，面向企业命题方交付有许可风险。
    （注：学习阶段用它理解检测原理无妨，但不得把其代码与权重带入交付物。）

## 2026-09-23 · 性能基准测试方法固定为 warmup + Event 计时

- **决定**：所有时延测量统一采用 `tools/bench.py` 的方法：
  warmup ≥10 次 → 多迭代 → `torch.cuda.Event` 计时 → `synchronize()` 后取均值。
- **理由**：首版测量未做 warmup，4096³ 矩阵乘测得 **156.8 ms / 2.0×**；
  修正后为 **12.79 ms / 10.5×**，一次性开销被误计入基准，**偏差 7.5 倍**。
  命题核心指标为端到端 ≤200 ms，测量口径错误将导致**全部**性能数据不可信。
- **备选与放弃原因**：
  - `perf_counter` host 侧计时：已弃用。CUDA 异步执行下它测的是**发射**而非**完成**。

## 2026-09-23 · 倍数指标必须同时报告两侧绝对值与运行条件

- **决定**：任何"提速 N 倍"的宣称，必须同时给出分子绝对值、分母绝对值和两者的完整运行条件。
- **理由**：实测中 GPU 绝对性能提升 64%（21.01 → 12.79 ms），但因为 CPU 侧同时被电源模式
  抬快，"倍数"反而从 **11.8× 降到 10.5×**。倍数是个比率，会随基准侧变化而**反向移动**。
  命题要求"综合推理速度相较**传统单节点架构**提升 3 倍以上"，
  若基准定义模糊，评委一句"你们那台对比机器是不是没调好"就能让该指标失效。
- **备选与放弃原因**：只报倍数（不报绝对值）——已否决，不可复现即不可信。

## 2026-09-23 · Windows 训练 + WSL2/Linux 练部署链路

- **决定**：D1–D4 训练在 Windows 本地进行；**D5 起（ONNX → ORT 推理）切到 WSL2 练习**；
  最终上板在 openEuler / 银河麒麟。
- **理由**：
  1. **昇腾 CANN 工具链（含 ATC 转换器）仅有 Linux 版本**，而方案中的降级路线
     `ATC 转 OM + AscendCL` 大概率会被用到（ORT 昇腾后端算子覆盖需实测）。
  2. 板子本身运行 Linux；参赛组别为"国产操作系统软件组"，国产 OS 是答卷的组成部分。
  3. mmcv 预编译轮子只有 manylinux 版本，Linux 下至少"源码编译"这条路是通的。
- **诚实提醒**：WSL2 是 `x86_64 / Ubuntu`，板子是 `aarch64 / openEuler`，**两者不等价**。
  板子上的 `.so` 与 wheel 必须是 aarch64，不能假设"WSL2 能跑 = 板子能跑"。
  → 应尽早对板子做一次 hello-world 级冒烟测试（SSH 登录 + 安装 Python + 跑通一次 ORT CPU 推理）。
- **备选与放弃原因**：全程 Windows —— 否决，ATC 无法运行，等于放弃降级路线。
